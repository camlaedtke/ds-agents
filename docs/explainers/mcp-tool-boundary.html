The tool boundary

Why run_python lives in another process, traced through one real call on the toy dataset.

The one sentence

Read this once, then press Next below and watch a single call cross the line.

MCP (Model Context Protocol — a fixed message shape for “an agent calls a tool”) lets an agent call code that is running somewhere else. The agent sends JSON; a separate server process does the work and sends JSON back. Nothing else passes between them.

This project puts its four tools behind that boundary instead of importing them as Python functions. It costs a whole phase of plumbing (PLAN.md Phase 2). It buys two things: the agents physically cannot reach the answer key, and a completely different agent can be handed the identical tool surface — which is what makes the team vs single_agent ablation mean anything.

the tool surface

Four names, four typed argument lists. That is everything an agent in this system can do to the world.

never exec

CLAUDE.md rule. Agent-written code never runs in the process that holds PipelineState. Section 2 shows what goes wrong if it does.

3. What the boundary is actually protecting

Two things, and only the second one is about safety.

the thingwith an MCP serverwith in-process functions
The ablation
RunConfig.arm = team vs single_agent		 Point Claude Code at the same server. One generalist agent, byte-identical tools. You write run_python twice. A gap in leakage_recall between arms could be the team, or could be the second implementation. Unfalsifiable.
The answer key
planted_leakage_columns, verified_holdout_score		 Not in the container. Not on the mounted filesystem. Not reachable. Sitting on the PipelineState object in the same Python heap the agent’s code runs in.
A runaway timeout_s kills the subprocess → exit_code ≠ 0 → a PipelineError row. A model-written while True hangs the whole eval. The hardest datasets vanish from the table.

The first row is the one DECISIONS.md leads with, and it is the one worth carrying: this is not primarily a security story. It is a measurement story. Findings are the product, and a finding that rests on two different tool implementations is not a finding.

mcp_server/ and src/ds_agents/tools/ are empty. Phase 1 calls tools/local.py, a shim with the same signatures. Phase 2 swaps the transport underneath and the toy run must stay green.

Still open (NEXT.md): Docker-per-run or one long-lived container. Per-run is cleaner to reason about and slower; long-lived is faster and lets state bleed between runs, which is exactly the kind of contamination the split_artifact pin exists to make falsifiable.
